Новые брони всем сотрудникам, которые запустили бота и ввели пароль доступа.

== Требования ==
Активные WooCommerce и JOYRENT Rentals 1.8.5 или новее.
Отдельный Telegram-бот через официальный @BotFather.
Сайт по HTTPS: Telegram должен иметь доступ к /wp-json/joyrent-telegram/v1/update.
Исходящие HTTPS-запросы к api.telegram.org и работающий WP-Cron / WooCommerce Action Scheduler.

== Установка и обновление ==
WordPress → Плагины → Добавить плагин → Загрузить плагин → joyrent-telegram-1.1.0.zip.
При обновлении выберите замену существующего JOYRENT Telegram.
Тема и JOYRENT Rentals не требуют замены, если Rentals не ниже 1.8.5.
Токен предыдущей версии сохраняется. После обновления настройте пароль и подключите бота.

== Подключение ==
1. Создайте отдельного бота в https://t.me/BotFather командой /newbot.
2. WooCommerce → JOYRENT → Telegram: сохраните токен и выбранный пароль доступа.
3. Нажмите «Подключить бота». Плагин подключит Telegram к защищённому адресу сайта.
4. Каждый получатель открывает бота, отправляет /start, затем вводит пароль.
5. Имена подключённых получателей появятся в списке подписчиков WordPress.
6. Нажмите «Отправить тест подписчикам» и дождитесь сообщения.
7. Включите «Отправлять новые брони подписчикам» и сохраните настройки.

ID чата вручную вводить не нужно. Подписка работает в личных сообщениях.
Каждая новая бронь отправляется всем активным подписчикам на момент её создания.
/stop отключает уведомления только для отправившего команду человека.
Повторная подписка не рассылает предыдущие брони.
После пяти неверных паролей подключение для этого аккаунта блокируется на 10 минут.
/start не обнуляет ограничение попыток.
При смене пароля все получатели должны подписаться заново, а администратор — снова включить рассылку.
Пустые поля токена и пароля при сохранении оставляют прежние значения.

== Сообщение о брони ==
Номер брони, контакты клиента и его дополнительный Telegram (если указан),
язык, консоль, даты, срок, геймпады, получение и адрес,
стоимость, условия доставки и залога, игры и пожелания.
Ссылка на бронь открывается в админке WordPress с авторизацией.
Уведомление не означает оплату или подтверждение наличия.

== Надёжность ==
Рассылка выполняется в фоне после завершения сохранения брони.
У каждого получателя свой статус: подтверждённая отправка, очередь, отказ или неизвестный результат.
Ошибка у одного подписчика не блокирует остальных.
Повтор формы клиента не создаёт вторую рассылку.
Telegram-подтверждения предотвращают повторную отправку уже доставленных уведомлений.
Явные временные отказы повторяются до четырёх попыток для каждого получателя.
При обрыве соединения автоматического повтора нет: Telegram мог уже получить сообщение.
Ручной повтор в карточке брони затрагивает только неподтверждённых активных получателей.
Для неизвестного результата перед повтором требуется проверка Telegram.
Смена токена, пароля или состояния включения останавливает старые ожидающие отправки.
Старые брони при включении не рассылаются. Email-уведомления продолжают работать.
Поддерживаются стандартное хранилище заказов и HPOS.

== Если бот не отвечает ==
Сохраните пароль и токен, затем повторите «Подключить бота».
Убедитесь, что сайт доступен по HTTPS и firewall не блокирует адрес Telegram webhook.
Используйте отдельного бота: подключение меняет его webhook.
После смены токена подключите бота повторно.
При проблемах с бронями проверьте группу joyrent-telegram в WooCommerce → Статус → Запланированные действия
и работу WP-Cron / Action Scheduler на хостинге.

== Приватность ==
Получатели с правильным паролем видят контакты клиентов. Передавайте пароль только сотрудникам.
Токен, хеш пароля и секрет webhook хранятся в закрытых настройках без autoload.
Входящие сообщения с паролем не сохраняются в базе плагина.
В списке подписчиков хранятся идентификатор Telegram, имя и дата подключения.
В заданиях очереди хранится только ID заказа или получателя, без токена и контактов.
Заказ хранит технические статусы рассылки и подтверждения Telegram.
Токен можно задать через JOYRENT_TELEGRAM_BOT_TOKEN в wp-config.php.
После сохранения токен и пароль не возвращаются в HTML или публичный REST API.
Удаление плагина удаляет настройки, список подписчиков и запланированные отправки.
Ранее отправленные сообщения остаются в Telegram; удалять их нужно отдельно.
Технические метаданные заказов сохраняются без паролей и токенов.
