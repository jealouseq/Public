# План улучшений JOYRENT после аудита 1.5

Это конкретный план следующей сборки, не список уже выполненных исправлений. Сохранить чёрно-белую палитру с тёплым светом, фото PS5/DualSense, Unbounded и Manrope, предоставленные цены и заявочный процесс с ручным подтверждением магазина. Новые блоки с рейтингами, счётчиками и рекламными обещаниями не нужны.

## Этап 1 Надёжная заявка и каталог

| Работа | Критерий приёмки |
|---|---|
| Отдельные стабильные кнопки перехода и отправки | На ПК/телефоне UA/RU первый переход не вызывает проверку пустых контактов. Заполненная форма → Назад → Далее даёт **0 POST**. Только явная отправка/разрешённая клавиатурная отправка на контактном шаге создаёт заявку. |
| Уведомление магазина | Локальная проверка события после успешного сохранения, затем проверка настроенного канала на тестовом хостинге. Одновременные повторы одного запроса создают один заказ и одно уведомление. Повтор после ошибки доставки уведомления не дублирует заказ. |
| Уникальные игры и защита миграции | REST не повторяет стабильные ID. Усі → На двох → Сюжетні → Перегони → Усі многократно показывает только ожидаемые игры, без накопления DOM. Перед очисткой сравнить управляемые записи; в текущем публичном каталоге пять пар одинаковы. Данные авторских игр и заявок не теряются. |
| Платформозависимые режимы | BO7: PS5=2, PS4=1; GT7: PS5=4, PS4=2. Фильтры и цифры меняются вместе с консолью. У BO7 коротко указана необходимость интернета. |
| Загрузка и повтор каталога | При отказе GET до заполнения контактов видна одна локализованная ошибка и «Повторить». При восстановлении GET черновик сохранён; отсутствующие игры удалены из выбора с понятным объяснением. Пустой опубликованный каталог остаётся пустым. |
| Единые ограничения списка игр | Любой список, который разрешено собрать интерфейсом, принимается серверной валидацией. Проверить 0/1/12/13 и все уникальные игры, несовместимую платформу, неизвестный ID и повторы. |
| Доступность отдельных тарифов | Черновик одного продукта скрывает только этот вариант. Оставшиеся тарифы принимают заявки. Удалённый выбранный срок заменяется доступным; отсутствие всех вариантов показано до контактов. |
| Одна логика доставки | При неизвестной короткой цене и бесплатном пороге 7: 3 дня = согласование, 7/30 дней = включено в зоне сервиса. Одинаковые результат UI и сохранённые данные WooCommerce. Проверить второй геймпад, самовывоз при его настройке и залог. |
| UA/RU правила и черновик | Полные ссылки открывают опубликованные страницы соответствующего языка. FAQ → возврат сохраняет консоль, срок, дату, игры и текущий шаг; контакты не сохраняются долговременно. При смене языка черновик не сбрасывается. У фиксированных UA/RU маршрутов корректный HTML lang. |
| Реальные условия магазина | До публичного запуска настроены город/зона, контакт, стоимость второго геймпада, короткой доставки и залог либо явно согласованный способ расчёта. Подтверждена доставка уведомления владельцу. |

## Этап 2 Связанный и читаемый интерфейс

Порядок главной сохранить: главный экран → тарифы → игры → комплект → получение/доставка → заявка → подвал. FAQ остаётся отдельным. Разделы каталога дают обзор; форма остаётся единым местом оформления.

- Выбор игр из заявки не уводит далеко вверх. Подборка доступна рядом с формой, закрытие/добавление возвращает в текущую позицию. Фокус клавиатуры предсказуем.
- Мобильная панель повторяет текущие консоль, срок и стоимость; кнопка ведёт к сохранённой форме. Итог не изменяется от перехода к каталогу или FAQ.
- На контактном шаге телефона оставить контакты и компактное редактируемое резюме. Не требовать пролистывать полный повтор выбора консоли/дат.
- Важные подписи/условия 13–14px, различимые границы полей. Невидимые области вторичных целей не меньше удобных 44px; видимые маленькие иконки могут остаться.
- Повтор «оплата не нужна» сократить до сообщения рядом с отправкой и результата. Отсутствие города заменить реальными условиями, а не новым абзацем общего текста.
- Кнопки тарифов сохраняют контур и шеврон; цвет, радиус, толщина иконок и hover остаются согласованными. Основные изображения и двухстрочный заголовок не обрезаются на 320–1920px UA/RU.

## Этап 3 Качество изображения и загрузки

- Сохранить утверждённую студийную композицию. Для мобильного подготовить 1448px WebP из текущего мастера; для большого DPR3 нужен реальный исходник минимум около 2104px, целевой около 2200px. Сравнить нативные детали, а не только изменившиеся размеры файла.
- Общий manifest используется React и PHP preload. В каждом размере скачивается одна подходящая hero-сцена; полные силуэты остаются видимыми.
- Превью игр получают responsive-размеры. Диалог сохраняет композицию обложки без зума, пустой рамки и изменения геометрии; полное изображение загружается при необходимости.
- Подготовить подходящий размер DualSense для телефона и ограничить первоначальную загрузку дальних элементов карусели. Сравнить сетевой вес до/после в одинаковых свежих контекстах, без ущерба качеству открытой карточки.
- Один короткий эффект заголовка, лёгкий hover карточки и медленное малое движение контроллера. Подсветку PS5 при необходимости оживить одним слабым циклом 8–12 секунд без движения изображения. Проверить prefers-reduced-motion и отсутствие рывков. Сложные шейдеры/частицы/новые библиотеки не добавлять.
- Упорядочить роли трёх используемых шрифтов Unbounded/Manrope/Onest и лишние устаревшие CSS-переопределения после проверки визуального соответствия. Удаление Onest возможно только после осознанной замены его служебных заголовков. На этой заявочной главной отдельно оценить необходимость стандартных WooCommerce frontend-скриптов; отключать их только на проверенных маршрутах, не затрагивая нужные страницы магазина.

## Проверка перед выпуском

1. Новые регрессии из этапа 1 плюс существующие frontend/TypeScript/PHP/REST/миграционные и конкурентные проверки.
2. Свежие ПК и мобильные UA/RU: заголовок, тарифы обеих консолей, фильтры многократно, длинная карточка игры, даты, второй геймпад, контактный шаг, ошибка/повтор и подтверждение.
3. Клавиатура, Escape, начальный/возвращённый фокус нативных диалогов; реальный iPhone/Safari перед публичным запуском. Chromium-эмуляцию не называть Safari-проверкой.
4. Установка обоих ZIP на тестовый WordPress и очистка кэша. Сверка каталогов и ассетов через публичные URL после развёртывания.
5. Одна заранее обозначенная тестовая заявка для проверки фактического уведомления на хостинге; снимки и персональные данные настоящих клиентов для этого не нужны.

Сначала выпуск с исправленной заявкой и данными; дополнительные календарные эффекты и визуальные варианты не должны задерживать устранение F01/F03/F12.
